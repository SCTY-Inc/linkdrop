A link inbox for humans and agents.

linkdrop is a small server you run yourself that saves the links you share from your phone as markdown files, for you and your agents to read later. Each capture goes to disk, and the server answers with a JSON receipt. Anything that can read a folder can read the inbox.

View on GitHub

The file is the database

Each capture is its own folder. The folder holds one capture.md with YAML frontmatter, plus the attachment if you sent a file. linkdrop writes a capture once and never rewrites it. If you send the same capture again on the same day, you get the first receipt back.

Quickstart

The server is one file that uses only Node's built-in modules, so there is nothing to install.

git clone https://github.com/SCTY-Inc/linkdrop && cd linkdrop
CAPTURE_DIR=~/linkdrop-inbox node server.js
curl -X POST localhost:18790/links -H 'content-type: application/json' -d '{"content":"https://example.com"}'

Requires Node 22 or later. Run the curl line in a second terminal. The server has no authentication, so keep it on a private network. To capture from a phone, point an iOS Shortcut at POST /links.

Why

Where should a link go when you are not ready to read it, and you want an agent to read it later?

Read-later apps keep links behind an account and a sync service. An agent can read a folder of markdown with no setup, so the inbox should be that folder.

Capture takes a link, some text or one file, writes it down and returns. It does not fetch the page or summarize it. A separate script, enrich.js, can fetch public context for one capture later. It writes an enriched.md next to the original and never overwrites one that exists.

Enrichment failed first on long X articles. It took two fixes before enrich.js saved the full article text. When it gets only a preview now, it writes nothing, so a reader who finds no enriched.md knows to open the link.

If you delete it tomorrow, you lose nothing

Your captures are plain files in CAPTURE_DIR. linkdrop does not need to run for you to read, grep, move or back them up. The quickstart keeps them in ~/linkdrop-inbox, outside the clone, so deleting linkdrop leaves them in place.
